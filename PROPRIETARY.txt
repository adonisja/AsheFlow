# PROPRIETARY.txt — the single source of truth for what must never be public.
#
# One repo-relative path per line. Blank lines and #-comments ignored.
#
# THIS FILE DRIVES THREE THINGS. Do not maintain any of them by hand:
#   1. .gitignore            — regenerated between the PROPRIETARY markers by
#                              scripts/sync_proprietary_lists.sh
#   2. private repo sync     — scripts/setup_private_repo.sh reads this file
#   3. CI exposure gate      — scripts/check_proprietary_exposure.sh fails the
#                              build if any path here is tracked publicly
#
# WHY THIS FILE EXISTS
# Before it, the same list was maintained in two places that had to agree by
# hand — .gitignore and a SERVICES array in setup_private_repo.sh. They drifted,
# twice, in opposite directions:
#
#   assign_captains.py   in NEITHER list  -> untracked publicly AND never synced
#                        to private, so CI could not import it and every test
#                        reaching routers.dispatch aborted collection.
#   run_sort.py          in SERVICES but NOT .gitignore -> synced to private
#   persist_zones.py     while ALSO sitting in the public repo. 556 and 478
#   sort_analysis.py     lines of proprietary logic, public since creation.
#
# A file being in one list and not the other is silent in both directions. One
# list, three consumers, and a CI gate that fails loudly is the fix.
#
# ADDING A FILE
#   1. Add the path here.
#   2. Run: bash scripts/sync_proprietary_lists.sh   (regenerates .gitignore)
#   3. Push. The pre-push hook syncs it to AsheFlow-private.
#   4. If it was already tracked: `git rm --cached <path>` and commit.
#      If it was already PUSHED, gitignoring is not enough — it stays in
#      history and needs a purge. See docs/decisions/ADR-265.
